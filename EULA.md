When the cloud knowledge base is active, AgentD also sends it search queries and `agentd ask` questions to retrieve records. (g) **Release checks and downloads**: with reporting on, the daily run checks for a newer release; `agentd upgrade` also requests release files and checksums when you run it. These requests identify the requested release, operating system and processor type in the URL. Downloads may follow redirects to the release mirror. (h) **Configured Runtime**: when you configure a Runtime, AgentD sends its login email and password or token to that address, probes health and capabilities, and sends ledger records, rules documents, search queries, agent definitions and questions to its knowledge and agent APIs. Configured notifications send notification titles (including excerpts of task goals or approval requests), item ids and dashboard links to Telegram or Gmail and the recipients; Telegram requests use the bot token and chat ids and poll and answer bot interactions, and Gmail uses the configured sender and app password to send mail, including invitation links you request. (j) **Hosting operations**: if you run AgentD's Job API or cloud worker, it requests account authentication, credit holds and settlement, model-key issuance and revocation, usage and balances from Console using service credentials and account/job identifiers; authentication also sends the account key. It requests repository installation tokens from GitHub and revokes them. Cloud workers exchange leases, repository and model credentials, status, results and cost with the Job API; they send repository traffic to the repository host, and, when a runner is configured, commands, environment variables and repository credentials to that runner to execute the job and push its branch. (k) **Commands you configure**: AgentD also runs verification checks and benchmark commands you configure, as well as configured watchdog restart commands. Depending on their permissions and configuration, these can read local files and environment variables and make network requests to other services; you control the destinations, data and Credentials those commands use. External tools AgentD launches, including worker clients and login-status probes, may also contact their vendors under those tools' own settings and terms. These commands and configured integrations operate independently of automatic reporting. Third-party services apply their own retention terms; LibraOS-hosted content follows Section 6.6, and you control storage in self-hosted Runtimes and runners. Automatic registration and daily reports do not include code, prompts, file paths, repository names or Outputs; registration does send your activation code in (a). The bundle redaction described in (d) is not a filter on feedback text, upload notes, knowledge queries, hosted task goals or model requests; do not include Credentials in them.
